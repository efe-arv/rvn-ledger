# Model use at 1000× scale

The current billing path makes no large language model (LLM) calls. The following is a proposed auxiliary layer, not an implemented feature. At 1000× volume, models should reduce investigation workload without becoming an authority over money.

**Quarantine investigation.** Code groups rejected records by deterministic reason, source and schema version where available, computes counts and impact, and selects bounded, redacted examples. Models can classify issue types, connect related groups, propose root-cause hypotheses and corrections, and recommend investigation priority. Each assessment should carry evidence references, model-reported confidence and a review status (pending, confirmed, rejected or revalidated). The original rejection reason remains authoritative; model interpretation is stored separately. Self-reported confidence is not a measured probability of correctness: calibrate it against human-reviewed examples, measure per-class errors and coverage, and abstain or escalate when evidence is insufficient. A high score alone never releases a record. Approved corrections create a versioned input that must pass the deterministic pipeline again.

**Choose the model for the task, not just an LLM.** Jev / TypeSafe System One-style decision models are candidates for typed classification, scoring and routing; evaluate decision accuracy, confidence calibration, latency, cost and abstention rather than prose quality. Generative models can explain evidence and draft remediation requests. Embedding and reranking models can retrieve similar reviewed incidents; statistical or specialist models can flag usage anomalies. These are candidates to benchmark on representative data, not claims of existing integration. An anomaly is an investigation signal, not proof of a billing error.

**Invoice explanations.** On request, code assembles invoice lines, applied rates, credits, audit references and computed period comparisons. A generative model translates that evidence into a readable explanation; every monetary claim must reference a computed field. Missing evidence must produce an explicit limitation, not an invented cause.

**Scale and safeguards.** Process bounded investigation units rather than every raw event. Run asynchronously with bounded queues, call budgets and retries; cache by evidence digest, task, prompt and model version. Record model identity, evidence and output separately from invoice artifacts. Treat source text as untrusted data, grant no write authority, and minimize sensitive data before any approved external processing. Provider failure must not block billing. Measure investigation accuracy, operator time saved and cost before rollout; retained provenance does not guarantee identical model responses on replay.

**Wrong uses.** Canonical-copy selection, validity and time-boundary checks, plan selection, tier arithmetic, rounding, credits, reconciliation and publication decisions stay in explicit code. Models must not silently repair inputs or change invoice totals. Deterministic billing and byte-reproducible artifacts must remain independent of probabilistic model output.
